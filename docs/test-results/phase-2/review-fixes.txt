### 4.2 R3 — drop the rowid tiebreak and see what the ordering test says

This one does **not** fail, and that is the point worth recording: with
`ORDER BY created_at ASC` alone SQLite happens to return same-second rows in rowid order
for this plan, which is exactly the incidental behaviour the review says the suite is
passing on. The clause makes the order contractual instead of lucky; the test pins the
contract, it is not a discriminator for the old code.

```
$ sed -i 's/ORDER BY created_at ASC, rowid ASC/ORDER BY created_at ASC/' internal/store/event.go
```

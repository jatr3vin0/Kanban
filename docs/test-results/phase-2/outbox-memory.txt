## Review fixes applied (architect review of PR #6, FIX-FIRST)

| Item | Change | Where |
|---|---|---|
| F1 (blocking) | A delivery transition commits even when its ticket has been deleted: one guarded `INSERT … SELECT … WHERE EXISTS (SELECT 1 FROM tickets WHERE id = ?)` helper, applied at all three audit call sites (ack, terminal failure, operator retry). The transition is never rolled back for want of an audit (C-AUDIT-9). | `internal/store/claim.go` (`insertAuditIfTicketExists`, `auditRowArgs`), `internal/store/outbox.go` (3 call sites) |
| F2 (blocking) | The delivery loop logs a failed iteration and continues; it returns only on context cancellation. `StartOutboxWorker` no longer discards the goroutine's terminal error — it logs it (`slog`, matching `main.go`'s default JSON logger). | `internal/store/outbox_worker.go` |
| F3 | The reclaim pre-pass clears `lease_owner` and `lease_expires_at` with the status, so an `uncertain` row is never rendered as leased to a worker that is gone. | `internal/store/outbox.go` (`ReclaimExpiredOutboxRows`) |
| F4 | The operator retry maps a residual driver error instead of surfacing it raw: a lock stays `database_busy` (C-ERR-7), anything else becomes a typed `internal` with the cause logged, never in the response (C-ERR-6). C-OUTBOX-13's 403/404/409 guards are unchanged. | `internal/store/outbox.go` (`retryOutboxErr`) |
| F5 | README states plainly that `MEMORY_DELIVERY=worker` is refused in v1 and that the mock adapter is test-only. | `README.md` |

### The defect, reproduced and then closed

Before the fix, deleting a ticket left its outbox rows (C-SCHEMA-13) with nowhere to write their
audit, so the ack rolled back and the row cycled `processing → uncertain → processing`, calling the
adapter every poll:

```
ack outbox row 9e9b5069a87d45ebab5de00af959593a: constraint failed: FOREIGN KEY constraint failed (787)
row status=processing attempts=1..3 external=<nil>   adapter calls = 3
```

### Falsifiability — each new regression test fails against the pre-fix code

Reverted the fix in a throwaway copy, ran the test, restored the tree (verified by `git status`):

```
== F2 reverted (runOutboxWorker returns on the first error): TestOutboxWorkerSurvivesErrors ==
--- FAIL: TestOutboxWorkerSurvivesErrors (0.01s)
    outbox_test.go: the loop returned after an iteration error instead of logging and continuing: sql: database is closed

== F1 reverted at the ack (unguarded insertAudit): TestOutboxDeliveryAfterTicketDeleted ==
--- FAIL: TestOutboxDeliveryAfterTicketDeleted (0.01s)
    Error: Received unexpected error:
           ack outbox row 9e9b5069a87d45ebab5de00af959593a: constraint failed: FOREIGN KEY constraint failed (787)
```

With the fix in place, the same test drains both rows in one attempt each — `succeeded`, external id
and `delivered_at` recorded, `attempts = 1`, two adapter calls for two writes, zero `ticket_events`
rows (the audit is skipped, not invented), and a second pass claims nothing.
